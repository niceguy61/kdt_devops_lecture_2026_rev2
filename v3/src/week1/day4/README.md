# 1주차 4일차 — 현대 애플리케이션 구조

## 오늘의 목표

어제는 요청이 서버까지 가는 **길**을 따라갔습니다. 오늘은 그 길 끝에 있는 **애플리케이션의 안쪽**을 엽니다. 쇼핑몰의 상품 페이지 하나는 화면 하나처럼 보이지만, 뒤에서는 프론트엔드, 백엔드 API, 데이터베이스, 캐시, 메시지 큐, 설정, 로그가 함께 움직입니다. 오늘은 국내 IT 기업들이 공식 기술 블로그에 공개한 사례를 길잡이로 삼아, **비즈니스가 커질 때 어떤 시스템 부담이 함께 커지는지**를 봅니다.

오늘의 숨은 제목은 이것입니다.

> **내가 가고 싶은 회사의 서비스는 코드 하나로 돌아가지 않는다.**

- 현대 애플리케이션의 구성요소 10가지를 구분할 수 있습니다.
- 프론트엔드와 백엔드의 역할, API와 상태 없는(stateless) 서버의 의미를 압니다.
- 스케일 업과 스케일 아웃, 가용성과 단일 장애점(SPOF)을 설명합니다.
- 관계형 DB와 NoSQL의 차이, CAP 정리의 핵심을 압니다.
- 캐시와 메시지 큐가 왜 필요한지, 동기와 비동기의 차이를 압니다.
- 모놀리식과 MSA의 장단점을 비교하고, 왜 2주차에 Docker를 배우는지 한 문장으로 말할 수 있습니다.
